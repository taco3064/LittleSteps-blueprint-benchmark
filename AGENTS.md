# LF benchmark requirements

These benchmark requirements override generic workflow suggestions below.

- Every enabled rule must remain `error`; keep the React preset thresholds.
- Run `npm run check` before committing: TypeScript, ESLint with zero warnings,
  `blueprint inspect` without baseline, and `blueprint doctor` must all pass.
- Never create a baseline, ratchet, suppression ledger, disable comment, rule
  downgrade, business-file ignore, or increased threshold to obtain a pass.
- The generated block mentions `inspect --baseline` as a generic capability.
  That mode is forbidden here: full `inspect` checks all current findings.
- Pin the vendored Blueprint repair candidate recorded in
  [the LF report](docs/benchmark-lf-report.md). Do not auto-upgrade to `latest`.
- Preserve product behavior and tests. Use the dummy Firebase browser setup and
  `demo-littlesteps` emulator only; no production credentials or deployment.
- Target `benchmark/lf` through a verified, reviewed PR. Never merge conversion
  code into `master`; keep `benchmark/mf` at its baseline until its separate run.
